## TL;DR

Mistral drops OCR 4 — directly relevant to your document ingestion stack. Claude Sonnet 5 and the GPT-5.6 series both landed earlier this week. Google is pushing hard on agentic Gemini (computer use, Gemini Omni), and MCP is getting a managed cloud deployment layer via Manufact.

## What's New

- **[Introducing Mistral OCR 4](https://mistral.ai/news/ocr-4/)** — Mistral is calling this their SOTA document intelligence model. No benchmark details in the announcement, but Mistral's OCR line has been competitive and this is directly in your lane — underwriting document ingestion, OCR, Azure AI Search. Worth a spike on your actual docs before committing to anything. `[TRY]`

- **[Anthropic Introducing Claude Sonnet 5](https://releasebot.io/updates/anthropic#Introducing-Claude-Sonnet-5)** — Sonnet 5 is out. Given your team runs Claude Code via AWS Bedrock, watch for Bedrock availability timing — new Anthropic models often lag a few weeks before reaching Bedrock GA. `[SHARE w/ engineering team]`

- **[Introducing Gemini Omni](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-omni/)** — Google's multimodal flagship. Paired with a computer use capability launching in Gemini 3.5 Flash (see below) — Google is clearly racing to match Claude's agentic surface area. No Bedrock angle here, but useful competitive context.

- **[Introducing computer use in Gemini 3.5 Flash](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-computer-use-gemini-3-5-flash/)** — Computer use is now in Gemini 3.5 Flash. Claude had this first; now it's table stakes. Relevant if any of your teams evaluate alternatives to Claude Code for agentic workflows. `[SHARE w/ engineering team]`

- **[How Amazon Bedrock catches AI-generated phishing](https://aws.amazon.com/blogs/machine-learning/how-amazon-bedrock-catches-ai-generated-phishing/)** — AWS writeup using Bedrock to detect AI-generated phishing at scale. Concrete, production-oriented use case — good fodder for leadership conversations about Bedrock ROI beyond code generation. `[SHARE w/ leadership]`

- **[Using DSPy to evaluate and improve Datasette Agent's SQL system prompts](https://simonwillison.net/2026/Jul/2/dspy-datasette-agent-prompts/#atom-everything)** — Simon Willison used DSPy to automatically evaluate and optimize agent system prompts. If you have RAG or SQL agents in your underwriting pipeline with hand-tuned prompts, this is the kind of systematic improvement loop that could matter. `[READ DEEPER]`

- **[Understand to participate](https://simonwillison.net/2026/Jul/2/understand-to-participate/#atom-everything)** — Geoffrey Litt's framing from AIE: as agents make larger and more complex changes, engineers accumulate cognitive debt if they stop tracking what the code actually does. His argument is that you need enough understanding to remain an active participant — not just a reviewer. This is the core culture challenge for your teams adopting Claude Code. `[SHARE w/ engineering team]` `[READ DEEPER]`

- **[Launch HN: Manufact (YC S25) – MCP Cloud](https://manufact.com)** — Manufact (formerly mcp-use) is positioning as "Vercel for MCP" — ship, iterate, test, and monitor MCP servers in production. Early-stage but worth tracking if your teams start building MCP servers for internal tooling. `[TRY]`
