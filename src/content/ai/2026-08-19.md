## TL;DR
Anthropic published five engineering posts today, including a new safer auto-permission mode for Claude Code and a look at how they contain agent blast radius — both worth 15 minutes given your rollout across teams. AWS Bedrock shipped two posts that land squarely in your document-ingestion lane: multi-agent classification for insurance documents and metadata-filtered contract search. Linear also released real usage data on how engineering teams use AI day to day.

## What's New
- **[How we contain Claude across products](https://www.anthropic.com/engineering/how-we-contain-claude)** — Anthropic's engineering breakdown of how they cap agent blast radius across claude.ai, Claude Code, and Cowork as agents get more capable. Useful frame for setting containment policy as you scale Claude Code to more teams. [READ DEEPER]

- **[How we built Claude Code auto mode: a safer way to skip permissions](https://www.anthropic.com/engineering/claude-code-auto-mode)** — new mode that skips permission prompts while keeping guardrails in place. Could cut friction for your teams without giving up the controls you need in a regulated environment. [TRY] — test it in a low-risk repo and compare against current permission settings.

- **[Scaling Managed Agents: Decoupling the brain from the hands](https://www.anthropic.com/engineering/managed-agents)** — architecture pattern for separating agent reasoning ("brain") from execution ("hands") at scale. Relevant reference point as you think through how agentic coding should be structured across your teams. [READ DEEPER]

- **[Implement vector-prompt document classification using Amazon Bedrock](https://aws.amazon.com/blogs/machine-learning/implement-vector-prompt-document-classification-using-amazon-bedrock/)** — a three-agent Bedrock pipeline (Strands Agents SDK) that combines Claude Haiku 4.5 textual analysis with Titan Multimodal Embeddings visual similarity to classify insurance policies and affidavits. This is close to a blueprint for your underwriting document classification step. [SHARE w/ engineering team]

- **[Improve contract search accuracy with auto-generated filters in Amazon Bedrock](https://aws.amazon.com/blogs/machine-learning/improve-contract-search-accuracy-with-auto-generated-filters-in-amazon-bedrock/)** — uses implicit/explicit filtering plus metadata-enriched chunking in Bedrock Knowledge Bases to ground contract search in the right legal context and access boundaries. Directly applicable to tightening RAG precision on regulated documents. [READ DEEPER]

- **[How Axonius built secure multi-tenant AI agents on Bedrock AgentCore](https://aws.amazon.com/blogs/machine-learning/how-axonius-built-secure-multi-tenant-ai-agents-on-bedrock-agentcore/)** — fully isolated, multi-tenant agents across hundreds of customer environments on AgentCore, without building custom compute isolation or auth from scratch. Worth knowing if you ever need per-business-unit agent isolation for compliance. [SHARE w/ leadership]

- **[Amazon Bedrock AgentCore payments is now generally available](https://aws.amazon.com/blogs/machine-learning/amazon-bedrock-agentcore-payments-is-now-generally-available-enabling-agents-to-transact-safely-and-autonomously-at-scale/)** — agents can now transact autonomously on Bedrock with spending guardrails and protocol-agnostic payment orchestration. Not directly relevant to document ingestion work, but a clear signal of where Bedrock's agent platform is headed. [SKIP]

- **[AI usage patterns in software teams](https://linear.app/data)** — Linear's data on how engineering teams actually use AI in day-to-day work. Useful ammunition when you talk adoption numbers with leadership. [SHARE w/ leadership]
