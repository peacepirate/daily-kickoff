## TL;DR

The week's biggest story wasn't a model release — it's Claude Code Auto Mode getting a public, roughly 80%-reliable bypass from prompt-injection researcher Johann Rehberger, one day after Anthropic's own post on how auto mode is supposed to contain risk. The Anthropic Engineering Blog is still stuck: the same five posts (containment, auto mode, managed agents, harness design, the April postmortem) have now run with zero new publish dates for at least three weeks straight — treat that feed as broken, not quiet, not a real signal of activity. AWS pushed Bedrock forward on two fronts relevant to your stack: AgentCore Evaluations (framework-agnostic agent scoring via OpenTelemetry) and OpenAI models running in-country in India, the same data-residency pattern worth knowing about if regional constraints come up here. Document/RAG tooling moved in small but real increments — Docling shipped two releases, Mistral launched an agentic retrieval product aimed at the same complex-document problem underwriting has, and Zep explained why they built a dedicated graph database for agent memory. Elsewhere, OpenAI cut Cursor off from its models after SpaceX's acquisition, reshuffling the coding-tool landscape, and LangChain shipped EU AI Act compliance guidance worth a skim given the regulatory ground you work on.

## Tier 1 — Primary Sources

- **[Our decision on Cursor following its acquisition by SpaceX](https://openai.com/index/our-decision-on-cursor-following-its-acquisition-by-spacex)** — OpenAI is winding down its contract supplying models to Cursor now that SpaceX owns it. Cursor will need to lean harder on its other model providers (including Anthropic via API/Bedrock). Reshuffles the coding-assistant competitive field without changing anything in your own stack directly.
- **[Introducing OpenAI models on Amazon Bedrock for in-country inferencing in India](https://aws.amazon.com/blogs/machine-learning/introducing-openai-models-on-amazon-bedrock-for-in-country-inferencing-in-india/)** — Bedrock now serves OpenAI's GPT-5.6 models with inference and data kept inside India via cross-Region routing. The mechanism, not the region, is the interesting part for a regulated shop watching data-residency requirements. [SHARE w/ leadership]
- **[Evaluate any agent framework with Amazon Bedrock AgentCore Evaluations](https://aws.amazon.com/blogs/machine-learning/evaluate-any-agent-framework-with-amazon-bedrock-agentcore-evaluations/)** — New Bedrock service scores agent quality from OpenTelemetry traces, so it works regardless of what framework built the agent. Low-effort eval coverage if you're already on Bedrock. [TRY]
- **[Agentic Search](https://mistral.ai/news/agentic-search/)** — Mistral's new retrieval layer for navigating, reading, and verifying information inside complex documents — same problem space as underwriting document ingestion. [READ DEEPER]
- **[Docling v2.123.1](https://github.com/docling-project/docling/releases/tag/v2.123.1)** — Patch release fixing VLM spacing and CSV BOM handling, on top of v2.123.0's bigger change: threaded `docling-parse` is now the default across the SDK, CLI, service, and extraction paths, plus tables/pictures now nest correctly inside form regions. [TRY]
- **[LangSmith LLM Gateway: Runtime Controls for Agents](https://www.langchain.com/blog/langsmith-llm-gateway-runtime-controls-for-production-agents)** — Public beta adding spend caps, rate limits, model fallbacks, and PII redaction in front of production agents, without provider lock-in. Relevant governance pattern regardless of whether you use LangChain.
- **[How LangSmith and LangChain OSS Help You Meet EU AI Act Requirements](https://www.langchain.com/blog/langsmith-langchain-oss-eu-ai-act)** — Walks through what the EU AI Act actually requires and maps it to concrete product features. Useful as a checklist even if your compliance obligations run through different regulators. [SHARE w/ leadership]
- **[Arize Phoenix has a built-in MCP server that lets your agents query traces with SQL](https://arize.com/blog/phoenix-mcp-sql-code-mode/)** — Read-only SQL and code mode let a coding agent answer questions across traces without paging thousands of spans into context. Useful pattern for observability around your own agent deployments.
- **[FinOps for the AI era: New flexible billing and cost controls for agents](https://cloud.google.com/blog/products/ai-machine-learning/flexible-billing-and-cost-controls-for-agents-on-google-cloud/)** — Google Cloud's answer to the "agents can spend unpredictably" problem: new billing flexibility and cost controls scoped to agent workloads. [SHARE w/ leadership]

## Tier 2 — Curator Picks

- **[Breaking Claude Code Opus 5 Auto Mode](https://simonwillison.net/2026/Aug/27/breaking-claude-code-opus-5-auto-mode/)** — Johann Rehberger's attack tricks Claude Code into downloading and unzipping an archive, then running code that imports `base64` in a way that slips past auto mode's containment checks. Works roughly 80% of the time. Auto mode is default-on and marketed as safe against exactly this. [SHARE w/ engineering team]
- **[Just a rumour of a bug is enough to find a security exploit these days](https://simonwillison.net/2026/Aug/28/just-a-rumour-of-a-bug/)** — An OCaml maintainer reports automated attackers probing for a vulnerability within about ten minutes of a patch being *discussed*, not even released. - **[Quoting Drew Breunig](https://simonwillison.net/2026/Aug/23/drew-breunig/)** — "Prior to Fable, it felt silly to waste too much time improving your coding harness... then Fable landed... the cost was so high [we] started to think about what work went where." Useful framing for how you route work across Bedrock model tiers by cost/complexity, not just capability.
