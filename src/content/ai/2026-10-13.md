## TL;DR

Busier day than usual. Anthropic put out two pieces worth your attention: an engineering post on containing agent blast radius, and a conference recap on how they coordinate multiple Claude agents on one project. Both land squarely on the governance and scaling questions you'll keep fielding as agentic coding spreads past your current 6-10 teams. AWS added a decision-model deployment pattern on SageMaker that's adjacent to your document-ingestion work, plus wider Bedrock access to OpenAI models in APAC.

## What's New

- **[How we contain Claude across products](https://www.anthropic.com/engineering/how-we-contain-claude)** — Anthropic's engineering team on capping what an agent can do as it gets more capable, across claude.ai, Claude Code, and Cowork. The closest thing to a reference model for "how far do we let Claude Code reach," which is exactly the question that gets harder as adoption widens. [READ DEEPER]

- **[How Anthropic's Dynamic Workflows Coordinate Claude Agents](https://www.latent.space/p/claude-dynamic-workflows)** — Recap of an Anthropic talk at AI Engineer New York: borrows Unix/Linux process-coordination ideas so agents can take on bigger projects without overwhelming the developer reviewing their work. A concrete pattern for multi-step agentic coding, not just single-shot prompting. [SHARE w/ engineering team] [READ DEEPER]

- **[Introducing Mistral Large 4](https://mistral.ai/news/mistral-large-4/)** — New flagship model from Mistral. No benchmark detail in the fetch; worth a glance if you evaluate non-Bedrock models for cost or latency comparisons. [SHARE w/ engineering team]

- **[Deploy decision models with llama.cpp on Amazon SageMaker AI](https://aws.amazon.com/blogs/machine-learning/deploy-decision-models-with-llama-cpp-on-amazon-sagemaker-ai/)** — Serves OpenAI-compatible chat completions via llama.cpp on SageMaker, extended to return probabilities over a declared set of options instead of free text. That's a classification pattern, closer to document decisioning (accept/reject/route) than open-ended generation. [TRY]

- **[Accessing OpenAI GPT models on Amazon Bedrock with global cross-Region inference in Thailand, Malaysia, Singapore, Indonesia, and Taiwan](https://aws.amazon.com/blogs/machine-learning/accessing-openai-gpt-models-on-amazon-bedrock-with-global-cross-region-inference-in-thailand-malaysia-singapore-indonesia-and-taiwan/)** — Bedrock now routes to OpenAI GPT models from five more APAC source Regions via the Converse and OpenAI-compatible APIs. Relevant if your org has APAC teams or data-residency considerations touching Bedrock. [SHARE w/ leadership]

- **[context-mode](https://github.com/mksglu/context-mode)** — GitHub Trending, 27.7k stars. Context-window optimization for AI coding agents: sandboxes tool output (claims 98% reduction), persists session memory, and routes across 17 coding-agent platforms via MCP + hooks. Worth a sandbox test given how much context your teams burn on large repos. [TRY]

- **[Modernizing complex legacy code with AI agents](https://mistral.ai/news/legacy-code-modernization/)** — Mistral case study on legacy modernization with agents. Same problem space as your adoption push; a useful outside data point for what "worked" looks like elsewhere. [SHARE w/ engineering team]

- **[How to test agent tool descriptions with Harbor and Phoenix](https://arize.com/blog/how-to-test-agent-tool-descriptions-with-harbor-and-phoenix/)** — Build a reproducible benchmark to check whether rewording a tool's description cuts unnecessary agent tool calls while preserving outcomes. Directly usable if you're tuning tool definitions for internal RAG/agent tooling. [READ DEEPER]
