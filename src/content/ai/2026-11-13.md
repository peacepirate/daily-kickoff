## TL;DR

Heavy Bedrock day: AWS published a cluster of posts on AgentCore's next-gen runtime, Managed Knowledge Base migration/access control, and cost governance — all directly relevant to your underwriting RAG pipeline. Mistral Large 4 and Gemini 4 Hydrogen were the week's model releases. ## What's New

- **[Introducing Mistral Large 4](https://mistral.ai/news/mistral-large-4/)** — New flagship model from Mistral, released alongside open weights ("Le Chonk") aimed at agentic coding and cybersecurity tasks. One of the few open-weight frontier-class releases this week. [READ DEEPER]
- **[Introducing Gemini 4 Hydrogen](https://deepmind.google/blog/introducing-gemini-4-hydrogen/)** — Google's cheapest Gemini 4 tier ($1.50/M input, $7.50/M output), now in Search. Useful as a cost comparison point when you're weighing model choice for cheaper pipeline stages. [SKIP]
- **[Run agents securely and efficiently with the next generation AgentCore runtime](https://aws.amazon.com/blogs/machine-learning/run-agents-securely-and-efficiently-with-the-next-generation-agentcore-runtime/)** — Hardware-isolated sessions, faster starts, usage-based billing, isolation extended to data. Companion case study: **[Natera's SWARM](https://aws.amazon.com/blogs/machine-learning/how-natera-designed-an-agentic-ai-system-for-lab-ops-with-amazon-bedrock-agentcore/)** built an agentic lab-ops system on AgentCore with ~130x faster first response and 96.2% automated ticket coverage. [SHARE w/ leadership]
- **[Migrate to Amazon Bedrock Managed Knowledge Base with your coding agent](https://aws.amazon.com/blogs/machine-learning/migrate-to-amazon-bedrock-managed-knowledge-base-with-your-coding-agent/)** — A coding-agent-driven migration path from customer-managed to Managed Knowledge Base, with read-only discovery and validation before cutover. Paired with **[fine-grained access control for KB tools](https://aws.amazon.com/blogs/machine-learning/fine-grained-access-control-for-amazon-bedrock-managed-knowledge-base-tools/)** via AgentCore Gateway and per-user identity checks — relevant to locking down your document RAG by role. [TRY]
- **[Four Amazon Bedrock inference choices that affect cost](https://aws.amazon.com/blogs/machine-learning/four-amazon-bedrock-inference-choices-that-affect-cost/)** — Cache duration, service tier, reasoning effort, and maxTokens, each tested for cost impact. Companion posts cover **[per-IAM-principal spend caps via CUR 2.0](https://aws.amazon.com/blogs/machine-learning/tokenomics-at-scale-track-and-cap-amazon-bedrock-spend-per-iam-principal-with-cur-2-0-and-aws-budgets/)** and **[proving agent ROI with a five-dimension scorecard](https://aws.amazon.com/blogs/machine-learning/optimizing-cost-per-task-and-proving-agent-roi-on-amazon-bedrock/)**. [SHARE w/ engineering team]
- **[How do you manage the context window in Claude Code and other coding agents — like a ninja](https://www.zyte.com/blog/how-to-manage-context-window-claude-code/)** — 18 context-management habits checked against the actual docs: /compact, /clear, caching, MCP. Directly testable against your own sessions. [TRY]
- **[Operate Claude Managed Agents inside your security perimeter](https://releasebot.io/updates/anthropic#Operate-Claude-Managed-Agents-inside-your-security-perimeter)** — New Anthropic platform launch for running managed agents within your own security boundary. Same-day Anthropic also announced **[Claude for Manufacturing](https://releasebot.io/updates/anthropic#Introducing-Claude-for-Manufacturing)** and **[Claude Meetings](https://releasebot.io/updates/anthropic#Introducing-Claude-Meetings)** — both vertical/consumer-facing, skip unless they come up. [SHARE w/ product team]
