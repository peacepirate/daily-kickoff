# AI Digest — Tuesday, May 19, 2026
*Coverage window: previous 24 hours*

## TL;DR
Google I/O 2026 delivered Gemini 3.5 and Gemini Omni — Google is all-in on the agentic era. AWS dropped three Bedrock/AgentCore posts directly relevant to your stack. DeepSeek previewed V4 with significantly improved agent capabilities.

## What's New

- **[Gemini 3.5: frontier intelligence with action](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-3-5/)** — Google released Gemini 3.5 Flash at GA (no preview phase) at I/O 2026, immediately deploying it across Search, the Gemini app, Android Studio, and the Gemini Enterprise platform. Simon Willison notes it's more expensive than 2.0 Flash but Google is betting it across their entire stack. Competitive context: this is the model your teams will increasingly hit when using Google tooling alongside Claude. [READ DEEPER]

- **[Introducing Gemini Omni](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-omni/)** — DeepMind unveiled Gemini Omni, a unified multimodal model positioned as Google's broadest-capability offering. Announced at I/O 2026 alongside 3.5 Flash; details remain sparse but it's the headline frontier model. Worth tracking for multimodal document processing relevance. [SHARE w/ engineering team]

- **[DeepSeek-V4 preview: world-class reasoning, major agent capability improvements](https://mp.weixin.qq.com/s/8bxXqS2R8Fx5-1TLDBiEDg)** — DeepSeek announced V4 preview with top-tier reasoning performance and significantly improved agent capabilities, live on web, app, and API. If V4 follows V3's trajectory, expect an open-weight release to follow — worth planning ahead for potential Bedrock availability. [READ DEEPER]

- **[Extending conversational memory in Kiro CLI using Amazon Bedrock AgentCore Memory](https://aws.amazon.com/blogs/machine-learning/extending-conversational-memory-in-kiro-cli-using-amazon-bedrock-agentcore-memory/)** — Shows how to build a custom MCP server that plugs Bedrock AgentCore Memory (fully managed, persistent) into any MCP-compatible agent. The pattern is directly portable to your teams' Claude Code setups: store and retrieve conversation context across sessions without managing your own memory store. [TRY] [SHARE w/ engineering team]

- **[Implementing programmatic tool calling on Amazon Bedrock](https://aws.amazon.com/blogs/machine-learning/implementing-programmatic-tool-calling-on-amazon-bedrock/)** — Three runnable patterns: self-hosted Docker sandbox on ECS for maximum control, managed AgentCore Code Interpreter, and an Anthropic SDK-compatible proxy for teams already using the Anthropic SDK. If your document ingestion pipeline needs sandboxed code execution, this post covers the full spectrum from full-control to fully-managed. [TRY] [SHARE w/ engineering team]

- **[Scalable voice agent design with Amazon Nova Sonic](https://aws.amazon.com/blogs/machine-learning/scalable-voice-agent-design-with-amazon-nova-sonic-multi-agent-tools-and-session-segmentation/)** — Three architectural patterns for voice agents (multi-agent, tool use, session segmentation) using Nova Sonic and Bedrock AgentCore, focused on minimizing latency. Less immediately relevant to document ingestion but useful context if any of your teams are building customer-facing voice interfaces on Bedrock. [SHARE w/ engineering team]

- **[Mistral Medium 3.5 + remote coding agents in Vibe](https://mistral.ai/)** — Mistral released Medium 3.5 alongside remote coding agents in their Vibe product and a new "Work mode" in Le Chat for complex tasks. Competitive context for evaluating open-weight model options; worth a look if you're assessing Mistral on Bedrock. [SKIP unless actively evaluating Mistral]

- **[Claude Code 2.1.133–2.1.144](https://releasebot.io/updates/anthropic/claude-code#2.1.144)** — Ten patch releases in the last 24 hours. No changelogs surfaced in source data. The pace suggests active iteration; check release notes directly if your teams hit unexpected Claude Code behavior. [SKIP for now]
