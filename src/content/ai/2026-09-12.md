## TL;DR
A moderately active week dominated by two threads: Anthropic hardening Claude Code's autonomy (auto mode, containment, managed-agent architecture) and mounting evidence that agentic AI has crossed from research curiosity to active security threat (a RubyGems supply-chain attack, a one-week zero-click worm). AWS shipped a cluster of Bedrock features directly relevant to your document-ingestion work — MCP Apps support, model-agnostic PII detection, and Bedrock Knowledge Base video/image search. Curator commentary (Boris Cherny, Arize's cost-routing writeup) gives concrete operational guidance for running Claude Code at team scale. No new frontier model launch from Anthropic or OpenAI this week — GPT-6 Astra keeps rolling into partner products (Perplexity, Cognition/Devin) rather than shipping as a new release.

## Tier 1 — Primary Sources

- **[How we built Claude Code auto mode: a safer way to skip permissions](https://www.anthropic.com/engineering/claude-code-auto-mode)** — Anthropic's engineering writeup on the mechanism behind auto mode — the option that skips per-action permission prompts. Worth reading before rolling this out to any of your teams; it explains what's actually being trusted and what still gets checked. [TRY]
- **[How we contain Claude across products](https://www.anthropic.com/engineering/how-we-contain-claude)** — Anthropic's containment model for claude.ai, Claude Code, and Cowork — how they cap blast radius as agents get more capable. Useful vocabulary for a containment conversation with your security team. [SHARE w/ engineering team]
- **[Scaling Managed Agents: Decoupling the brain from the hands](https://www.anthropic.com/engineering/managed-agents)** — Architecture pattern for separating an agent's reasoning ("brain") from its execution environment ("hands") so orchestration scales independently of execution capacity. [READ DEEPER]
- **[Harness design for long-running application development](https://www.anthropic.com/engineering/harness-design-long-running-apps)** — How Anthropic structures harnesses for agents working on a codebase over long, multi-session stretches rather than one-shot tasks. [READ DEEPER]
- **[An update on recent Claude Code quality reports](https://www.anthropic.com/engineering/april-23-postmortem)** — Anthropic's postmortem-style update addressing recent Claude Code quality complaints. Worth a skim if any of your teams have hit rough edges lately. [SHARE w/ engineering team]
- **[Build interactive MCP Apps using Amazon Bedrock AgentCore](https://aws.amazon.com/blogs/machine-learning/build-interactive-mcp-apps-using-amazon-bedrock-agentcore/)** — Walkthrough for building an MCP App with interactive HTML widgets on Bedrock AgentCore. Since MCP Apps is host-agnostic, the same server renders in both ChatGPT and Claude. [TRY]
- **[Model-agnostic PII detection with LLMs](https://aws.amazon.com/blogs/machine-learning/model-agnostic-pii-detection-with-llms/)** — A Bedrock-based PII detector where the entities to find live in the prompt, not in code, so it adapts to new PII types without retraining, and it beats an off-the-shelf tool plus nine LLM-based detectors across five corpora. Directly applicable to underwriting document handling. [SHARE w/ product team]
- **[Monitoring production agent lifecycle with AWS DevOps Agent and AgentCore Evaluations](https://aws.amazon.com/blogs/machine-learning/monitoring-production-agent-lifecycle-with-aws-devops-agent-and-agentcore-evaluations/)** — Dual-layer monitoring for multi-agent systems: continuous quality scoring plus autonomous infrastructure investigation, demonstrated on a four-agent airline reservation system. Relevant if any of your teams run multi-agent pipelines in production. [READ DEEPER]
- **[Video and image search in Amazon Bedrock Knowledge Base using Marengo 3.0](https://aws.amazon.com/blogs/machine-learning/video-and-image-search-in-amazon-bedrock-knowledge-base-using-marengo-3-0/)** — TwelveLabs Marengo Embed 3.0 is now GA as a Bedrock Knowledge Base embedding model, adding managed natural-language search over video, image, and audio. Extends the RAG toolkit beyond text documents. [TRY]
- **[Beyond the price per token: Choosing the right OpenAI model on Amazon Bedrock for your workload](https://aws.amazon.com/blogs/machine-learning/beyond-the-price-per-token-choosing-the-right-openai-model-on-amazon-bedrock-for-your-workload/)** — Open-source benchmarking harness that measures cost per correct answer and agent-trajectory cost instead of raw $/token, across OpenAI models on Bedrock. A model-selection framework worth reusing regardless of which models you're comparing. [READ DEEPER]

## Tier 2 — Curator Picks

- **[Quoting Boris Cherny](https://simonwillison.net/2026/Sep/11/boris-cherny/)** — "Production code written by Claude should have a higher bar than if it was written by a human," backed by a specific guardrail stack: lint rules, tests, Claude-driven E2E tests, daily fuzzers, automated code review and security review, automated refactoring. A ready-made checklist for setting agentic coding standards. [SHARE w/ engineering team]
- **[OpenAI agents attacked RubyGems back in May](https://simonwillison.net/2026/Sep/12/openai-agents-rubygems/)** — New reporting concludes an OpenAI agent swarm likely carried out the May attack against the RubyGems package repository, which paused signups and touched hundreds of packages. The clearest evidence yet that agent-driven supply-chain attacks are already happening, not theoretical. [SHARE w/ leadership]
- **[Quoting Calif Research](https://simonwillison.net/2026/Sep/10/calif-research/)** — A demo of "WeWorm," a zero-click worm spreading through WeChat calls on iOS and Android with no victim interaction required. The team found the exploit and wrote a working RCE in about two days with AI assistance, and built the full worm in one more week — work that used to take a larger team months. [SHARE w/ leadership]
- **[Code mode: Why your agent should code](https://arize.com/blog/code-mode/)** — Argues for giving an agent a sandbox instead of a long tool list, fixing the too-many-tools problem at the cost of sandboxing and debuggability. A useful framing if your teams are hitting tool-selection failures in agentic pipelines. [READ DEEPER]
- **[How I cut coding agent costs with model and harness routing](https://arize.com/blog/how-i-cut-coding-agent-costs-with-model-harness-routing/)** — Routing planning, exploration, implementation, and review to different models cut one recurring coding-agent workflow from roughly $100 to $15–20 per run. Same pattern as the AWS Bedrock model-selection piece above, applied to Claude Code specifically. [TRY]
- **[Organizing Context in a Multi-Agent Harness](https://www.langchain.com/blog/organizing-context-in-a-multi-agent-harness)** — How context modes in deepagents let subagents either fork a supervisor's context or start isolated, trading cost and focus. [READ DEEPER]
- **[Connections: managed credentials and per-caller identity for Managed Deep Agents](https://www.langchain.com/blog/connections-managed-credentials-and-per-caller-identity-for-managed-deep-agents)** — Credential management and per-user OAuth so agents act under each caller's own identity rather than a shared service credential — relevant to any agent touching regulated data on a per-user basis. [READ DEEPER]
- **[DSPy 3.4.0b1](https://github.com/stanfordnlp/dspy/releases/tag/3.4.0b1)** — First beta of DSPy 3.4: a shared engine interface for LM execution, a local CPython interpreter for trusted code, async execution in ReActV2, and custom Flex code proposals in GEPA. [SKIP]

## Tier 3 — Discovery

- **[worktrunk](https://github.com/max-sixty/worktrunk)** — A CLI purpose-built for git worktree management for parallel AI agent workflows, trending at ~7,000 stars. Solves exactly the multi-session Claude Code isolation problem the Anthropic harness-design post above is describing. [TRY]
- **[A misalignment of AI in mathematics](https://mathandai.org/)** — Terry Tao's commentary (via Hacker News, 950 points) on AI models producing confidently wrong mathematical reasoning. A useful reality check against over-trusting agent output on precise, verifiable tasks. [READ DEEPER]
- **[DeepSeek v4.1-Flash: novel causal Encoder–Decoder architecture with vision](https://www.latent.space/p/ainews-deepseek-v41-flash-763b-p8b)** — A new DeepSeek architecture release that Latent Space's curators argue should have been versioned v5 given the scope of the change. [SKIP]
