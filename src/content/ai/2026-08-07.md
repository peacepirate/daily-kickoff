# AI Digest — Friday, August 07, 2026
*Coverage window: previous 24 hours*

## TL;DR
AWS shipped a cluster of Bedrock AgentCore governance features today — temporal policies, a new open-source policy language (Dogwood), and gateway rate limits — aimed squarely at the "how do I put guardrails on an agent I don't fully trust" problem. Anthropic followed with a Claude Code auto-mode deep dive and a note on running Claude Code sessions on remote compute. A PDF-classification library also hit GitHub Trending that slots directly into your document-ingestion triage step.

## What's New
- **[Control agent behaviors and cost beyond a single action: new capabilities in Amazon Bedrock AgentCore](https://aws.amazon.com/blogs/machine-learning/control-agent-behaviors-and-cost-beyond-a-single-action-new-capabilities-in-amazon-bedrock-agentcore/)** — Temporal policies (rules that evaluate authorization based on an agent's session history, not just the current action) plus gateway rate limits, both powered by a new open-source policy language called Dogwood. This is deterministic cost/behavior control that holds regardless of what the agent decides mid-session. [SHARE w/ engineering team]
- **[Enforcing data residency with single-Region Claude Code on Amazon Bedrock](https://aws.amazon.com/blogs/machine-learning/enforcing-data-residency-with-single-region-claude-code-on-amazon-bedrock/)** — Walkthrough for pinning Claude Code inference to one AWS Region (not just in-geography), using either an application inference profile or the Mantle endpoint plus an IAM Region condition, with CloudTrail verification. Directly applicable if any of your document-ingestion work touches regulated data residency requirements. [SHARE w/ leadership]
- **[Agent Skills for Automated Reasoning policies in Amazon Bedrock](https://aws.amazon.com/blogs/machine-learning/agent-skills-for-automated-reasoning-policies-in-amazon-bedrock/)** — Open source Agent Skills that let a coding agent build, review, test, debug, deploy, and validate an Automated Reasoning policy end to end — turning a console-only task into a repeatable engineering workflow. [TRY]
- **[How we contain Claude across products](https://www.anthropic.com/engineering/how-we-contain-claude)** — Anthropic's writeup on capping agent blast radius across claude.ai, Claude Code, and Cowork as capability grows. A useful governance framework to bring into conversations with the teams you lead. [READ DEEPER]
- **[How we built Claude Code auto mode: a safer way to skip permissions](https://www.anthropic.com/engineering/claude-code-auto-mode)** — Engineering breakdown of auto mode, a more constrained alternative to blanket permission-skipping. Worth understanding before any team leans on auto-approve for speed. [TRY]
- **[An update on recent Claude Code quality reports](https://www.anthropic.com/engineering/april-23-postmortem)** — Anthropic's postmortem on recent Claude Code quality issues. Relevant context if any of your teams hit rough patches and want to know what Anthropic found and fixed. [SHARE w/ engineering team]
- **[Anthropic — Run Claude Code sessions on your own compute](https://releasebot.io/updates/anthropic#Run-Claude-Code-sessions-on-your-own-compute)** — New option to execute Claude Code sessions on infrastructure you control rather than Anthropic-hosted compute. [SHARE w/ engineering team]
- **[firecrawl / pdf-inspector](https://github.com/firecrawl/pdf-inspector)** — Rust library that classifies PDFs as scanned vs. text-based before extraction, enabling smart routing decisions. That's exactly the triage step your OCR/RAG pipeline needs. [TRY]
