## TL;DR

Anthropic published two engineering posts worth your time: how Claude Code's auto mode skips permissions safely, and how they contain agent blast radius across products — both map directly to rolling out agentic coding in a regulated shop. AWS shipped Bedrock AgentCore updates for agent evaluation and cross-account knowledge bases. Mistral's new Agentic Search targets the same complex-document retrieval problem you're solving for underwriting.

## What's New

- **[How we built Claude Code auto mode: a safer way to skip permissions](https://www.anthropic.com/engineering/claude-code-auto-mode)** — Anthropic's own account of the safety rails behind auto mode's permission-skipping. Worth reading against your own rollout policy for the teams you lead — this is the exact tradeoff (velocity vs. blast radius) you're managing at org scale. [TRY]

- **[How we contain Claude across products](https://www.anthropic.com/engineering/how-we-contain-claude)** — How Anthropic caps what an agent can do across claude.ai, Claude Code, and Cowork as capability grows. Directly relevant framing for a regulated environment where "what can this agent touch" is a compliance question, not just an engineering one. [SHARE w/ engineering team]

- **[Evaluate any agent framework with Amazon Bedrock AgentCore Evaluations](https://aws.amazon.com/blogs/machine-learning/evaluate-any-agent-framework-with-amazon-bedrock-agentcore-evaluations/)** — New Bedrock service scores agent quality via OpenTelemetry traces, so it works regardless of framework (LangGraph, Claude Agent SDK, Strands, etc.). If you're on Bedrock already, this is a low-effort way to get eval coverage on whatever agents your teams have built. [TRY]

- **[Connect Amazon Bedrock AgentCore to cross-account knowledge bases](https://aws.amazon.com/blogs/machine-learning/connect-amazon-bedrock-agentcore-to-cross-account-knowledge-bases/)** — Lets an AgentCore agent in one AWS account query a Bedrock knowledge base (backed by Redshift Serverless) in another account, without copying source data. Relevant if your underwriting RAG data and compute live in separate accounts for compliance reasons. [SHARE w/ engineering team]

- **[Agentic Search. More accurate and efficient results from your AI systems.](https://mistral.ai/news/agentic-search/)** — Mistral's new retrieval layer for navigating and verifying information inside complex documents. Same problem space as document ingestion/RAG for underwriting — worth a close read for approach comparison, not necessarily adoption. [READ DEEPER]

- **[Docling v2.123.0](https://github.com/docling-project/docling/releases/tag/v2.123.0)** — Now nests tables and pictures inside form regions by default, and threaded parsing is the new default across the SDK/CLI/service. If Docling or a similar layout-aware parser is anywhere in your OCR pipeline, the form-region change is worth checking against your document types. [READ DEEPER]

- **[Claude in Chrome is generally available](https://releasebot.io/updates/anthropic#Claude-in-Chrome-is-generally-available)** — Browser extension moves from preview to GA. [SHARE w/ all teams]

## Personal / Side-Project Watch

- **[Ollama v0.33.1](https://github.com/ollama/ollama/releases/tag/v0.33.1)** adds MLX support for Qwen3.8-Flash-Next, and Simon Willison has a [first-look writeup](https://simonwillison.net/2026/Aug/26/qwen38-flash-next/) running it on a DGX Spark — a large MoE model (125B total, ~6B active) that's newly practical to run locally. Worth a look if you're still poking at local LLM setups for Gods of the Future Past tooling.
