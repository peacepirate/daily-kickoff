## TL;DR

AWS and Anthropic shipped the real news today: a new Bedrock API for enrolling in Enterprise Frontier Safeguards and Enterprise Data Controls, giving you a formal data-governance lever for regulated workloads. Mistral dropped Large 4 as open weights, and Docling pushed another OCR/parsing release worth testing against your underwriting pipeline. Everything else — a new model architecture from Z.ai, a local-model/database integration from Google, a consumer Search tweak — is lower priority.

## What's New

- **[Introducing the Amazon Bedrock Trusted Access API](https://aws.amazon.com/blogs/machine-learning/introducing-the-amazon-bedrock-trusted-access-api-with-anthropics-enterprise-frontier-safeguards-and-enterprise-data-controls/)** — A single API to discover, request, and enroll in model-provider programs on Bedrock. The first two, in public preview, are Anthropic's Enterprise Frontier Safeguards and Enterprise Data Controls — direct levers over how your data is handled when calling Claude on Bedrock. [SHARE w/ leadership]

- **[Le Chonk: Built for Coders, Trusted by Defenders](https://mistral.ai/news/mistral-large-4-oss/)** — Mistral released Large 4's weights, aimed at agentic coding and cybersecurity defense. An open-weight option worth knowing about if any team ever wants an on-prem or local alternative to Bedrock-hosted models. [SHARE w/ engineering team]

- **[Docling v2.152.0](https://github.com/docling-project/docling/releases/tag/v2.152.0)** — Native MLX support for Nemotron 3.5 Parse, plus fixes for pdfium keeping words beside tall cells and separating right-to-left text runs. Incremental, but it's your document-ingestion toolchain. [TRY]

- **[How to build a knowledge factory for AI agents](https://www.langchain.com/blog/knowledge-factory)** — LangChain's pattern for keeping an agent's company knowledge current: agents flag what's missing, a curator agent fixes it in the background. A reproducible design for RAG-corpus upkeep rather than a one-off demo. [READ DEEPER]

- **[Data + AI Anywhere: AlloyDB Omni integration with local models](https://cloud.google.com/blog/products/databases/alloydb-omni-integration-with-local-models/)** — Google's Postgres-compatible AlloyDB Omni now integrates with locally hosted LLMs (e.g. Gemma 4), for agentic workloads that need to stay on-prem. Worth knowing as a fallback pattern if any underwriting data can't leave your infrastructure. [READ DEEPER]

- **[GLM-5.4: Toward Generalized Coding with Our First Loop Transformer](https://simonwillison.net/2026/Nov/23/glm-54/)** — Z.ai's new model reuses a group of weight-shared layers across multiple iterations instead of running each layer once, going deeper without adding parameters. New architecture, no action needed yet — second "loop transformer" mention this week per Simon Willison.

- **[A more tailored Google Search that's uniquely yours](https://blog.google/products-and-platforms/products/search/google-search-personal-intelligence-apps/)** — Google Search now pulls personal context from Gmail, Drive, Photos, and Calendar into results. Consumer UX shift, no action needed. [SKIP]

## Personal / Side-Project Watch

- **[Ollama v0.40.18](https://github.com/ollama/ollama/releases/tag/v0.40.18)** — Faster Metal decode, prefill, and draft rounds for local inference on Apple Silicon, plus fused residual mixing for the Inkling architecture. Relevant if you're still running models locally on your Mac.
