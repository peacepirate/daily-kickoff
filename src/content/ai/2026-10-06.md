## TL;DR
Two items matter for your regulated Bedrock setup: Opus 5.5 and Sonnet 5.5 now run in AWS GovCloud for Claude Code, and GLM 5.3 landed on Bedrock. The retrieval posts from AWS and Mistral are the ones to read for the underwriting pipeline. Claude Code shipped ten releases (2.1.282–2.1.291), but the fetched data has version numbers only.

## What's New
1. **[Claude Code 2.1.282–2.1.291](https://releasebot.io/updates/anthropic/claude-code#2.1.291)** — Ten Claude Code releases in this window. The fetched data has no changelog text, so the changes are unknown. Read the 2.1.291 notes before the next team update. [READ DEEPER]
2. **[Supercharge regulated workloads with Claude Code and Amazon Bedrock](https://aws.amazon.com/blogs/machine-learning/supercharge-regulated-workloads-with-claude-code-and-amazon-bedrock/)** — Opus 5.5 and Sonnet 5.5 are available on Bedrock in AWS GovCloud (US), for use with Claude Code on regulated and ITAR workloads. If your account can use GovCloud, this is the compliance-aligned path. Confirm with your security team before anyone relies on it. [SHARE w/ engineering team]
3. **[Introducing GLM 5.3 on Amazon Bedrock](https://aws.amazon.com/blogs/machine-learning/introducing-glm-5-3-on-amazon-bedrock/)** — A 753B-parameter mixture-of-experts model from Z.ai, built for coding and long-running agentic tasks. Bedrock exposes it through OpenAI-compatible APIs, with prompt caching for cost and latency. Test it against Sonnet 5.5 on one of your own coding tasks. [TRY]
4. **[How we contain Claude across products](https://www.anthropic.com/engineering/how-we-contain-claude)** — Anthropic on capping the blast radius of agents as they get more capable, covering claude.ai, Claude Code, and Cowork. Useful input for the guardrails your teams need when agents have write access. [READ DEEPER]
5. **[Agentic retrieval with LangChain and Amazon Bedrock Knowledge Bases](https://aws.amazon.com/blogs/machine-learning/agentic-retrieval-with-langchain-and-amazon-bedrock-knowledge-bases/)** — Shows where agentic retrieval beats single-shot RAG on multi-part questions, with trace events and per-path cost comparisons. This is the closest match to the underwriting retrieval problem. [TRY]
6. **[Agentic Search — Mistral](https://mistral.ai/news/agentic-search/)** — A retrieval layer for navigating, reading, and verifying information across complex documents. The fetched summary is short. Read the post for the method before comparing it with your current retrieval. [READ DEEPER]
7. **[docling v2.134.0](https://github.com/docling-project/docling/releases/tag/v2.134.0)** — Adds Apple Numbers input, exposes logprobs on the streaming VLM path, and fixes several docx extraction bugs. If your ingestion handles Word files, the extracted text changes. [SHARE w/ engineering team]
8. **[Beam: Reflection's 501B open-weight model](https://reflection.ai/blog/introducing-beam)** — A new open-weight model from Reflection, listed at 501B parameters. It is too large for a laptop, so its value to you is as a US-built open option for hosted or on-prem use. [READ DEEPER]
