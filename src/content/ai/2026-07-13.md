# AI Digest — Monday, July 13, 2026
*Coverage window: previous 24 hours*

## TL;DR
Amazon Bedrock had a loaded day: GPT-5.6 went GA, and AWS published a real production agentic case study (Bluesight) plus a multi-tenant agent security pattern — all squarely in your document-ingestion lane. Mistral shipped a dedicated OCR 4 model worth benchmarking against your pipeline, and a wave of skill/prompt-governance tools (Mistral Studio, Sx 2.0, several trending GitHub repos) is emerging around the exact problem you're solving scaling Claude Code across 6–10 teams. Codex adoption numbers give you fresh context for the next agentic-coding conversation with leadership.

## What's New

- **[OpenAI GPT-5.6 Sol, Terra, and Luna are now generally available on Amazon Bedrock](https://aws.amazon.com/blogs/machine-learning/openai-gpt-5-6-sol-terra-and-luna-are-now-generally-available-on-amazon-bedrock/)** — GPT-5.6's three model variants are now GA on Bedrock's next-gen inference engine, sitting in the same console as your Claude models. `[TRY]` Run your existing OCR/extraction eval set against GPT-5.6 Sol and compare accuracy/latency to your current Claude baseline — no new procurement needed.

- **[Introducing Mistral OCR 4](https://mistral.ai/news/ocr-4/)** — Mistral's latest "state of the art" document intelligence model. Directly in your lane — worth a side-by-side accuracy test against your OCR pipeline on dense tables and handwritten fields, though it's not on Bedrock, so you'd need direct API access to trial it. `[TRY]` `[READ DEEPER]`

- **[Implement on-behalf-of token exchange for multi-tenant agents with Amazon Bedrock AgentCore Gateway](https://aws.amazon.com/blogs/machine-learning/implement-on-behalf-of-token-exchange-for-multi-tenant-agents-with-amazon-bedrock-agentcore-gateway/)** — Full implementation guide for OBO token exchange against Okta, with JWT claim transforms and audience binding for defense in depth. Applicable if your document-ingestion agents ever need to act with per-tenant identity instead of one shared service credential. Pairs with DeepMind's broader post on [securing AI agents](https://deepmind.google/blog/securing-the-future-of-ai-agents/) if you want the threat-model context first. `[READ DEEPER]`

- **[Building an agentic AI solution at Bluesight with Amazon Bedrock](https://aws.amazon.com/blogs/machine-learning/building-an-agentic-ai-solution-at-bluesight-with-amazon-bedrock/)** — Bluesight went from a single-product AI prototype to Prism, a six-product agentic healthcare compliance platform on Bedrock AgentCore, already live at 20 health systems. A concrete answer if leadership asks what "production agentic AI" looks like outside a demo. `[SHARE w/ leadership]`

- **[[AINews] Codex usage up >10x in 6 months to 7M users, +1M in the past ~day; did Codex overtake Claude Code??](https://www.latent.space/p/ainews-codex-usage-up-10x-in-6-months)** — Latent Space's roundup flags Codex's growth curve and notes Anthropic's own usage reporting has gone quiet by comparison. OpenAI also shipped [ChatGPT Work](https://releasebot.io/updates/openai#ChatGPT-Work:-Take-on-your-most-ambitious-tasks), an enterprise tier pitched at "ambitious tasks" — read as agentic positioning aimed at the same buyers evaluating Claude Code. Worth a number in your pocket before the next adoption conversation. `[SHARE w/ leadership]`

- **[datasette code-frequency chart on GitHub](https://simonwillison.net/2026/Jul/13/datasette-code-frequency/#atom-everything)** — Simon Willison pulled up his own OSS project's GitHub code-frequency chart and found a visible output spike aligned with his adoption of Opus 4.8/GPT-5.5/GPT-5.6-class models. Anecdotal, but a rare concrete visual for coding-agent productivity impact — worth borrowing for your internal agentic-adoption narrative. `[SHARE w/ leadership]`

- **[Your Prompts and Skills need a system of record](https://mistral.ai/news/manage-prompts-and-skills-in-studio/)** — Mistral's Studio versions and tracks prompts/skills as first-class artifacts. The same day, a Show HN project, [Sx 2.0](https://sleuth-io.github.io/sx/2026/07/10/your-dropbox-is-now-a-skill-server.html), tackled the same problem for non-technical teams sharing Claude/Codex skills via a synced folder instead of git — and GitHub trending is full of Claude Code skill repos right now ([hallmark](https://github.com/Nutlope/hallmark), [graphify](https://github.com/Graphify-Labs/graphify), [marketingskills](https://github.com/coreyhaines31/marketingskills)). This is exactly the problem you hit scaling skills across 6–10 teams. `[TRY]` Test Sx 2.0 with one team that's newer to Claude Code — see if a folder-based skill share removes their git-onboarding friction.

- **[Building Food Metadata with LLM Juries](https://careersatdoordash.com/blog/building-food-metadata-with-llm-juries-context-optimization-multimodal-ai/)** — DoorDash uses multiple models voting/scoring in parallel ("juries"), plus context optimization, to generate structured metadata from multimodal inputs at scale. The ensemble-scoring pattern is transferable to boosting confidence on your OCR/extraction outputs for underwriting docs. `[READ DEEPER]`
