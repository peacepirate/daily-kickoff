Anthropic's engineering blog had an unusually heavy day: five posts covering agent containment, managed-agent architecture, auto mode, and long-running harness design — all directly relevant to scaling agentic coding across your teams. AWS shipped Bedrock and SageMaker updates that map onto your document AI stack: prompt-based PII detection, video/image RAG search, and a multi-turn agent evaluation metric. No new model releases today.

## What's New

- **[How we built Claude Code auto mode: a safer way to skip permissions](https://www.anthropic.com/engineering/claude-code-auto-mode)** — Anthropic's design for letting Claude Code skip permission prompts without giving up guardrails. Worth testing before you decide whether to recommend it to teams that find permission prompts a friction point. [TRY]

- **[An update on recent Claude Code quality reports](https://www.anthropic.com/engineering/april-23-postmortem)** — Postmortem on recent Claude Code quality issues. If any of your teams have flagged flakiness, this explains what happened and what changed. [READ DEEPER]

- **[How we contain Claude across products](https://www.anthropic.com/engineering/how-we-contain-claude)** — How Anthropic caps the blast radius of agents across claude.ai, Claude Code, and Cowork as capability grows. Directly speaks to the "what happens if the agent does something wrong" question your leadership will ask about agentic coding adoption in a regulated shop. [SHARE w/ leadership]

- **[Scaling Managed Agents: Decoupling the brain from the hands](https://www.anthropic.com/engineering/managed-agents)** — Architecture pattern separating agent reasoning from execution. Relevant as you scale agentic coding past 6–10 teams and start hitting the limits of one-agent-does-everything. [READ DEEPER]

- **[Harness design for long-running application development](https://www.anthropic.com/engineering/harness-design-long-running-apps)** — Patterns for keeping agents coherent over long-running dev tasks, not just single-shot edits. [SHARE w/ engineering team]

- **[Model-agnostic PII detection with LLMs](https://aws.amazon.com/blogs/machine-learning/model-agnostic-pii-detection-with-llms/)** — A configurable PII detector where entity types live in the prompt, not code, so it adapts without retraining. Outperformed nine LLM-based detectors and an off-the-shelf tool across five corpora. Directly applicable to scrubbing PII in underwriting documents before they hit downstream RAG. [TRY]

- **[Video and image search in Amazon Bedrock Knowledge Base using Marengo 3.0](https://aws.amazon.com/blogs/machine-learning/video-and-image-search-in-amazon-bedrock-knowledge-base-using-marengo-3-0/)** — TwelveLabs' Marengo 3.0 is now a managed embedding model in Bedrock Knowledge Bases, extending semantic search to video, image, and audio. Only relevant if document ingestion scope ever expands beyond OCR'd text. [READ DEEPER]

- **[Agent Evaluation Metric for multi-turn conversations](https://aws.amazon.com/blogs/machine-learning/agent-evaluation-metric-for-multi-turn-conversations/)** — A turn-level metric that pinpoints which turn in a multi-turn agent conversation caused a failure, instead of scoring the whole conversation as one pass/fail. Useful if you're building eval harnesses for your own agents. [SHARE w/ engineering team]
