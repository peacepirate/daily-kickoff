## TL;DR
Anthropic published two more engineering posts on Claude Code auto mode and agent containment — same themes as yesterday, worth a skim if you missed them. AWS shipped a mortgage-lender case study on automated document intake and a pattern for mining resolved support tickets into a knowledge base, both close analogs to your underwriting document pipeline. Docling and LangSmith also shipped incremental but relevant tooling updates.

## What's New
- **[Automate Document Processing with Quick Automate and the IDP Accelerator](https://aws.amazon.com/blogs/machine-learning/automate-document-processing-with-quick-automate-and-the-idp-accelerator/)** — walkthrough of a mid-size mortgage lender automating its entire document intake pipeline (email → classify → extract → validate) using the AWS GAIIC IDP Accelerator and Amazon Quick Automate. Close to a blueprint for the underwriting document ingestion work. [READ DEEPER]

- **[How we built Claude Code auto mode: a safer way to skip permissions](https://www.anthropic.com/engineering/claude-code-auto-mode)** — Anthropic's engineering writeup on the mode that skips permission prompts while keeping guardrails. Same post flagged yesterday; still worth testing before wider rollout. [TRY]

- **[How we contain Claude across products](https://www.anthropic.com/engineering/how-we-contain-claude)** — how Anthropic caps agent blast radius across claude.ai, Claude Code, and Cowork as agents get more capable. Useful framing for containment policy conversations in a regulated shop. [SHARE w/ leadership]

- **[KnowledgeForge: mining gold from the ITSM ticket graveyard](https://aws.amazon.com/blogs/machine-learning/knowledgeforge-mining-gold-from-the-itsm-ticket-graveyard/)** — mines resolved support tickets into new knowledge base articles and curates the existing library (dedup, quality-score) using Bedrock, S3 Vectors, and Step Functions in a closed-loop pipeline. Same RAG-maintenance problem you'd hit with any long-lived underwriting knowledge base. [READ DEEPER]

- **[Domain and publish date filters for Web Search on AgentCore](https://aws.amazon.com/blogs/machine-learning/domain-and-publish-date-filters-for-web-search-on-agentcore/)** — Bedrock AgentCore's Web Search tool now supports per-request domain and freshness filtering, server-side. Also now live in Europe (Ireland) and Asia Pacific (Tokyo). [SHARE w/ engineering team]

- **[Docling v2.121.0](https://github.com/docling-project/docling/releases/tag/v2.121.0)** — improved OCR input selection, a page-rotation fix for text-cell coordinates, and new Apple Pages (.pages) support. Direct doc-AI/OCR tooling update if Docling is in your extraction stack. [TRY]

- **[smolmachines / smolvm as a sandbox for untrusted Python & JavaScript](https://simonwillison.net/2026/Aug/19/smolmachines-untrusted-sandbox/)** — Simon Willison's research task (run via Claude Fable 5 in Claude Code) into using smolmachines as a fast, secure sandbox for untrusted code: CPU/RAM caps, no network, filesystem allowlist only. Relevant if any team lets agents execute generated code. [READ DEEPER]

- **[Introducing LangSmith Tuned Evaluators](https://www.langchain.com/blog/introducing-langsmith-tuned-evaluators-starting-with-perceived-error)** — attaches quality feedback to production agent traces, starting with a "Perceived Error" signal, to help teams find and fix agent mistakes. Relevant to evaluating agentic coding or RAG output quality at scale. [SHARE w/ engineering team]

## Personal / Side-Project Watch
- **[Ollama v0.32.15](https://github.com/ollama/ollama/releases/tag/v0.32.15)** and **[llama.cpp b10524](https://github.com/ggml-org/llama.cpp/releases/tag/b10524)** — Ollama added a model metadata cache to cut per-request overhead; llama.cpp made MoE expert scatter deterministic on OpenCL and landed `ggml_rope_set_offset` support across CUDA/Metal/Vulkan. Incremental, but worth knowing if you're still experimenting with local LLM setups.
