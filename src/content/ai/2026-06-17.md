# AI Digest — Wednesday, June 17, 2026
*Coverage window: previous 24 hours*

## TL;DR
AWS Summit NYC dropped multiple Bedrock announcements today — AgentCore gains broader knowledge access, continuous learning, and production observability for agents. DeepSeek-V4 preview is live with claimed world-class reasoning and improved Agent capabilities. GitHub trending surfaces `codebase-memory-mcp`, an MCP server that indexes entire codebases into a persistent knowledge graph in milliseconds.

## What's New

- **[New in Amazon Bedrock AgentCore: Build agents with broader knowledge and continuous learning](https://aws.amazon.com/blogs/machine-learning/new-in-amazon-bedrock-agentcore-build-agents-with-broader-knowledge-and-continuous-learning/)** — Three new capability areas announced at AWS Summit NYC: connectors for organizational, web, and paid knowledge sources; production observability to find and fix what's going wrong in running agents; and governance controls that scale as agents grow more capable. This directly maps to the gap your teams likely hit — agents that work in the sandbox but struggle with real enterprise data access in prod. `[TRY]` `[SHARE w/ engineering team]`

- **[DeepSeek-V4 preview released](https://mp.weixin.qq.com/s/8bxXqS2R8Fx5-1TLDBiEDg)** — DeepSeek claims world-class reasoning performance and significantly improved Agent capabilities in their V4 preview, now live on web, app, and API. No architecture details yet, but given DeepSeek's track record on V3, this is worth tracking for cost/performance benchmarking against Claude on Bedrock. `[SHARE w/ engineering team]`

- **[Amazon SageMaker AI Async Inference now supports inline request payloads](https://aws.amazon.com/blogs/machine-learning/amazon-sagemaker-ai-async-inference-now-supports-inline-request-payloads/)** — You can now send inference payloads directly in the `InvokeEndpointAsync` API body instead of uploading to S3 first. For your doc ingestion pipeline, this removes a round-trip step on shorter documents and simplifies the call flow considerably. `[TRY]`

- **[Introducing Gemini Omni](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-omni/)** — Google launches Gemini Omni, a new multimodal model. No content details available in the source yet, so treat this as a flag to investigate. Worth tracking for your OCR/document AI work given Google's multimodal strengths. `[SHARE w/ leadership]`

- **[DeusData/codebase-memory-mcp](https://github.com/DeusData/codebase-memory-mcp)** — Trending MCP server that indexes codebases into a persistent knowledge graph: 158 languages, sub-ms queries, claims 99% fewer tokens vs. naive context stuffing, ships as a single static binary with zero dependencies. If it holds up under real use, this is plug-and-play context compression for your teams' Claude Code workflows — no setup overhead. `[TRY]`

- **[GLM-5.2 is probably the most powerful text-only open weights LLM](https://simonwillison.net/2026/Jun/17/glm-52/#atom-everything)** — Z.ai released GLM-5.2 under MIT license yesterday: 753B MoE model (40B active params), 1M context window, up from 200K in GLM-5.1. Simon Willison calls the benchmark buzz "strong." Not immediately actionable on Bedrock, but relevant if you evaluate open-weight models for cost control or on-prem cases. `[READ DEEPER]`

- **[mattpocock/skills](https://github.com/mattpocock/skills)** — Matt Pocock's personal `.claude` skills directory, now public with 133K stars. Worth a 10-minute scan for patterns and techniques to adapt when building shared skills libraries for your teams' Claude Code workflows. `[READ DEEPER]`

## Personal / Side-Project Watch

GLM-5.2's MIT license and 1M context window makes it the current best open-weights option for local LLM experiments. The [Latent Space write-up](https://www.latent.space/p/ainews-glm-52-the-top-frontend-coding) has benchmark context if you're evaluating it for anything outside Bedrock.
